## 1. 从现有软硬件反推的业务画像（我们已知的）

### 1.1 硬件构成与规模

| 设备 | 数量 | 角色 |
| --- | --- | --- |
| 真空负压表（Modbus RTU，从站 1~72） | 72 | 每工位一路真空度采集 |
| 真空电磁阀（DO Y000~Y107） | 72 | 每工位独立控制真空通断 |
| 载台上电继电器（DO Y110~Y217） | 72（9排×8列） | 给载台各分区产品供电 |
| IO 耦合器 GX-CL140 | 1 台（80DI/160DO） | 全部阀/电/DI 的汇聚 |
| 冷却送风机（Modbus TCP:50000） | 1 台 | 读温湿度 + 定值启停（无温度设定下发） |
| 扫码枪 Xenon 1902 | 1 把 | SN 绑定录入 |

### 1.2 推断的产品与工艺特征（待现场证实）

- 产品需**真空吸附在载台上 + 通电**工作 → 典型如电源类/充电类/贴合类电子产品；
- 默认阈值 -5kPa 属较弱真空（V1.61 前随意填的 -95kPa 已作废，之前基于"接近极限真空→强吸附"的推断不再成立）——
  到底是**治具吸附固定（兼顾贴面散热）**还是产品自身气密性检验，**这两种用途决定"漏气报警"的物理含义完全不同，必须现场确认**；
- 送风机带温湿度反馈、配方有"极限温度"参数 → 存在温度相关工艺（加热老化 or 冷却保护，方向待确认）；
- 单工位独立阀+独立上电 → 支持"任意子集启停"，即**流水式（做完一个换一个）与整炉式（一批同进同出）两种模式软件都能支撑**，操作习惯待确认。

## 2. 行业通识：电子制造老化测试的标准业务流程

老化（Burn-in/Aging）通用八步，用于对照找差距：

```
①装夹上线 ──► ②扫码绑定 ──► ③选配方 ──► ④启动老化 ──► ⑤过程监控 ──► ⑥到时完成 ──► ⑦数据追溯 ──► ⑧异常处理
 (人工摆料)   (SN↔工位↔批号)  (工艺参数)  (真空→确认→上电  (压力/温度巡检  (下电→破真空→   (报表/直通率/   (急停/断电恢复/
                                          →送风→计时)     +报警联动)     取件换料循环)    MES回传)        重测/报废)
```

每一步的关键决策点（现场要逐条问到的）：

| 步骤 | 决策点 | 本项目现状 |
| --- | --- | --- |
| ①装夹 | 治具形式、有无到位传感器（DI） | 无到位检测，纯人工目视 |
| ②扫码 | 批号规则、混批允许否、要不要 MES 校验路由 | 有录入批号+SN绑定，无 MES |
| ③选配方 | 谁有权改参数（工艺员 vs 操作员） | 已有权限分级，颗粒度待确认 |
| ④启动 | 真空建立判定（延时够 vs 压力到位才算） | V1.59 已实现"真空到位(配方阈值)+延时开启到"双条件才上电；到位前超时报警且全程不带电（现场只需验证延时/阈值是否合工艺） |
| ⑤监控 | 泄漏判定标准、温度超限动作范围（单位 or 整线） | 压力报警单工位联动✅；温度联动范围待确认 |
| ⑥完成 | 到时自动下电？自动提示？人工确认后才算完？ | V1.59 已实现：到时自动下电关阀→"已完成·待取料"蓝色面板；手动停止=中止回空闲（现场确认取件前要不要自动泄压） |
| ⑦追溯 | 报表格式、直通率统计口径、保存年限 | 有 CSV 明细+历史查询，无汇总报表；判定口径 V1.59：全程无报警=PASS、压力报警=FAIL、通讯失联=设备异常(不记产品FAIL) |
| ⑧异常 | 中途断电来电后怎么办（续跑 or 重跑 or 作废） | V1.59 已实现 TestSession.json 快照：重启询问"整台重测/放弃(安全关阀断电)"，策略=整台重测（评审结论） |

## 3. 缺口分析：已实现 vs 待确认（本 Plan 核心）

| # | 环节 | 现状 | 待确认问题 | 若答案不同的影响 |
| --- | --- | --- | --- | --- |
| G1 | 载台上电 | 只是 DO 开关量 | 给产品供什么电（DC 多少V？经继电器接通外部电源？）；**要不要回采电流/功率作为老化监测项** | 要回采 → 需加电流表/功率计通讯，工作量最大项 |
| G2 | 真空作用 | 按压力报警处理 | 真空是"吸附固定散热"还是"产品气密检验"？漏气算治具问题还是产品不良？**另需确认：装夹摆料阶段是否就依赖真空吸附（如立式/挂壁载台一松手就掉）？** | 气密检验 → 报警要关联 SN 记不合格，涉及判定逻辑；**装夹依赖真空 → 需加回"装夹预吸附"入口**（V1.59.1 已删手动"开启真空"按钮，理由见其 CHANGELOG；若恢复必须带压力监控+随启动接管进状态机，不做游离态） |
| G3 | 启动时序 | 开阀→延时→上电（固定延时） | 真空建立要不要"压力到位"才算就绪？个别工位建不起真空怎么办（等待/跳过/报警） | 要到位判定 → StartTesting 状态机需加"等待确认"态 |
| G4 | 完成语义 | 有倒计时显示 | 到时后：自动下电+关阀+标完成？还是只提醒人工处理？完成后要不要自动破真空（泄压）方便取件 | 自动化程度决定 UI 与状态机改造量 |
| G5 | 合格判定 | 无 | 老化合格的判定标准是什么？（全程无报警即合格？）谁判定、在哪判定 | 决定要不要"结果"字段与判定引擎 |
| G6 | 批次模式 | 支持任意子集 | 流水式还是整炉式？批号与 SN 的对应（一 SN 一批 or 多 SN 共批）？混批允许吗 | 影响报表口径与录入交互 |
| G7 | 温度工艺 | 只读温湿度+启停 | 送风目的是加热老化还是冷却保护？设定温度谁来定（风机本地面板 vs 软件）？极限温度超了动作范围（单位下电 or 全线停） | 软件设温 → 现协议无写温度寄存器，需厂商支持 |
| G8 | 报警处置 | 报警即关阀断电标故障 | 报警后产品处置流程：重测/报废/降级？复位权限归谁？ | 影响复位流程与权限设计 |
| G9 | 外部对接 | 无 | 要不要对接 MES/ERP/客户系统？接口形式（DB/HTTP/文件）？ | 有对接 → 单独排期，别现场答应死 |
| G10 | 报表 | CSV 明细 | 质量部要什么报表：日产能/直通率/老化曲线/SN 追溯单？格式 Excel？ | 决定报表模块设计 |
| G11 | 断电恢复 | 未定义 | 老化中断电来电：剩余时间续跑？整批作废重跑？ | 需要持久化"在测任务"，影响架构 |
| G12 | 节拍 | — | 单批老化时长？每天几批？几班倒？旺季峰值？ | 校验 72 工位容量与界面刷新策略合理性 |

> G1/G2/G3/G4/G5 为 **P0**：任何一个答案变化都会改变业务串联逻辑的设计。
