## 1. 项目全景：一句话、规模、技术栈

### 1.1 一句话

一台工控机软件，同时监控 **72 台真空负压表**的压力，控制 **72 路真空电磁阀 + 72 路载台电源**，外加一台冷却送风机和一把扫码枪，完成"上料→抽真空→上电老化→完成/报警→下料"的**老化测试业务闭环**。

### 1.2 设备规模一览

| 设备 | 数量 | 怎么连 | 在代码里是谁 |
| :--- | :---: | :--- | :--- |
| 真空负压表（气压表） | 72 | Modbus RTU，RS485 转 CH340 USB，**19200 8N1**，从站地址 = 设备号 1~72 | `Services/ModbusRtuBarometerReader.cs` |
| IO 耦合器 | 1 | 三菱 GX-CL140，Modbus TCP `192.168.1.20:502`，80 路输入 / 160 路输出 | `Services/ModbusTcpIoController.cs` |
| 冷却送风机 | 1 | 厂商控制屏，Modbus TCP 端口 **50000**（注意不是 502） | `Services/FanControllerClient.cs` |
| 扫码枪 | 1 | Honeywell Xenon 1902，虚拟串口 **115200**，WMI 自动找串口 | `Services/ScannerService.cs` |

### 1.3 技术栈

- **.NET Framework 4.7.2**（注意：是老 Framework，不是 .NET Core / .NET 5+，别用新语法新 API），语言 C#，界面 WinForms。
- 界面库 **SunnyUI 3.9.8**（好看的第三方 WinForms 控件，但有一堆"和原生不一样"的坑，第 5.6 节细讲）。
- 通讯库 **NModbus 3.0.83**（Modbus RTU/TCP 都用它）。
- 序列化 **Newtonsoft.Json 13**（所有 JSON 落盘都用它）。
- 报表导出 **DocumentFormat.OpenXml 3.5.1**（历史记录导出 xlsx 用）。
- 串口设备识别 **System.Management**（WMI 查 CH340 / 扫码枪串口）。
- 构建：MSBuild 编译 `AgingTestSystem/AgingTestSystem.csproj`（老式项目，**新增 .cs 文件必须手工在 csproj 里登记一行**，否则报 CS0246 找不到类，第 8.1 节讲）。

## 3. 设计理念：6 条军规（理解这些，代码随便看）

### 3.1 军规一：配置双轨制——"跟机器还是跟项目"，这是最重要的规则

程序里有两类配置，住在**两个不同的地方**，走**两套不同的读写路径**。每次加配置项，第一件事就是问："它是接线事实，还是工艺要求？"

| | 跟机器（接线事实） | 跟项目（工艺要求） |
| :--- | :--- | :--- |
| 举例 | 串口号、波特率、IP 地址、设备数量、串口超时 | 真空超时、报警阈值策略、完成判定口径、MES 字段映射、配方 |
| 住哪 | `App.config`（exe 同目录的 `*.exe.config`） | `Projects/<项目名>/Policy.json`（exe 目录下的 `Projects/` 文件夹） |
| 内存唯一源 | 都是 `Models/DeviceConfig.cs` 这一个对象 | 同左（启动时两层叠加进同一个对象） |
| 加载顺序 | 先读 `App.config`（机器缺省） | 再用 `Policy.json` 覆盖（**项目赢**） |
| 切项目换不换 | 不换（换一台工控机才变） | 换（切项目即换工艺） |
| 名单出处 | `SettingsForm` 的 `_boolKeys` / `_numericKeys` 等 | `Services/ProjectPolicyStore.cs` 的 `PolicyKeys`（23 个，**唯一名单**，分流/校验/叠加全认它） |

加载顺序记住一句话：**App.config（机器缺省）→ Policy.json（项目覆盖）→ DeviceConfig 内存**。`Policy.json` 里写了啥就听啥，没写就回退缺省；文件坏了/丢了 = 当空处理，全回缺省，**不抛异常**（现场不能因为一个配置文件坏了就开不了机）。

跟项目还是跟机器，一张速查表（加东西时对照）：

- 跟项目：`Recipes.json`（配方库）、`StationSettings.json`（工位缓存）、`Policy.json`（策略）、`CustomPolicy.json`（自定义策略槽）。
- 跟机器：`Users.json`（用户，密码是哈希）、`TestSession.json`（断电恢复快照）、`Logs/`（日志/CSV）、`BarometerPort.cache` / `FanLastIp.cache`（连接记忆）、`MainSetting.ini`（激活）。
- 纯代码固定、不跟文件：主页布局、工位面板布局（改布局 = 改代码重编译，项目未上线，不留"文件覆盖代码"的第二套口径）。

> 为什么这样设计？一台工控机可能给多个产品型号做老化（多个"项目"），工艺参数随产品换，但串口/IP 是这台机器的接线事实，换产品时不能变。双轨制就是把"变的"和"不变的"分开。

### 3.2 军规二：判定与执行分离——纯函数先行

这是代码里最漂亮的一条约定，也是二开时最容易违反的一条：

- **判定类逻辑**（该不该上电、该不该报警、该不该完成）一律写成 `Services/AgingSequencer.cs` 里的 **static 纯函数**：只进参数、只出结果，不碰 IO、不碰全局变量、可单测。
- `Services/DeviceManager.cs` 只做三件事：**调用决策 + 发 IO + 记日志**。

举例（`AgingSequencer.cs`，建议现在就打开看，它的注释写得很好）：

```csharp
// 该不该上电：延时<=0 直接上电；否则"真空到位 + 延时到了"双条件
bool ShouldPowerOn(bool pressureInRange, TimeSpan elapsedSinceValveOpen, int delaySeconds)
// 该不该完成：时长<=0 永不自动完成（不限时长，靠人工停）
bool ShouldComplete(TimeSpan elapsedSincePowerOn, int durationSeconds)
// 真空建立是否失败：超时<=0 表示"关闭此检查，不限时等"
bool IsVacuumBuildFailed(bool pressureInRange, TimeSpan elapsed, bool valveOpen, int confirmTimeoutMs)
// 报警两级压制：L1 关=越限不报；L2 开=一切报警全压住
bool ShouldSuppressAlarm(bool muteAllAlarms)
```

注意一个反复出现的语义：**`0 = 关闭/不限`**。`VacuumConfirmTimeoutMs=0` 表示不限时等，`MaxTestDurationSeconds=0` 表示不限时长手动停。新加"超时/时长"类配置时，沿用这个语义，别发明第三种。

### 3.3 军规三：接口隔离 + Mock，一键脱离硬件

所有硬件驱动都实现 `Interfaces/` 下的接口：

```csharp
interface IBarometerReader  // 气压表：Connect / Disconnect / ReadData / ReadAllData / SetThreshold / SetAllThresholds / OnError
interface IIoController     // IO耦合器：Connect / Disconnect / ReadInput(s) / WriteOutput(s) / ReadOutput(s) / OnError
interface IFanController    // 送风机：Connect / Disconnect / ReconnectNow / ReadStatus / StartFixedValue / Stop / OnError
interface IPowerMeter       // 电流表：预留骨架，目前只有 Mock/桩实现，无真实驱动
```

每个接口都有 `MockXxx` 实现（`Services/Mock*.cs`）。`MainForm` 启动装配时看 `UseMockCommunication` 开关决定 new 真实还是 Mock。**新加设备必须照抄这个六件套**（`IsConnected + Connect(DeviceConfig) + Disconnect() + ReconnectNow() + 读/写方法 + OnError 事件），读失败返回 null（别抛异常），`Connect` 失败返回 false（别抛异常）。Mock 优先于开关？不——**显式注入优先于开关**，开关只在装配层传 null 时生效（别在 Mock 里做使能判断）。

### 3.4 军规四：共享连接——全程序只有 DeviceManager 能建连接

`DeviceManager` 是唯一持有真实 TCP/串口连接的对象。通讯测试窗、送风机测试窗**不许自己建第二路连接**，一律调 `DeviceManager` 透出的门面：

```csharp
EnsureIoConnected() / IsIoConnected / ReadHoldingRegisters() / WriteSingleRegister()   // IO
ReconnectFan() / GetFanData() / StartFan() / StopFan() / IsFanConnected                 // 风机
```

为什么？两路 TCP 连同一个 Modbus 从站会互相抢、状态各说各话；测试窗读风机状态走的是 2 秒轮询缓存，**零额外报文**。新开测试/调试窗必须遵守这一条。

### 3.5 军规五：落盘原子写 + 绝对路径

- 运行时 JSON 一律 `AtomicFile.WriteAllText`（先写临时文件再改名替换），**禁止裸 `File.WriteAllText`**。原因：写一半断电，下次启动读到半截文件会解析失败回空——配方被清空、策略全回缺省，等于按错误工艺跑。唯一的例外是激活的 `MainSetting.ini`（走 kernel32 INI API，和 HJVision 工具保持同文件）。
- 运行时文件路径一律 `BaseDirectory` 绝对路径，**禁止裸文件名**（裸文件名跟随"当前工作目录"，快捷方式的"起始位置"一变就写散、重启找不到，整批任务静默丢失）。

### 3.6 军规六：事件一次批量 + 边沿日志

- `DeviceManager` 每采集轮触发一次 `OnBatchDataUpdated(BarometerData[])`（72 台一个数组一次送达），**禁止逐台触发 72 次 UI 切换**。
- 心跳/轮询日志**只记边沿**（连上记一行、断开记一行，中间稳态静默）。如果你发现日志里每秒都在刷同一句话，那就是 bug，要收成边沿。

## 4. 通讯接入逻辑：四台设备 + 两扇测试窗

> 本节讲"代码怎么连"。寄存器地址、功能码、接线细节以 `docs/通讯接入.md` 为准（它是协议唯一出处）；本节讲类、方法、调用链和坑。

### 4.1 总览：启动时谁连谁（调用链）

```
MainForm.LoadConfig()            读 App.config + Policy.json 叠加 + 参数钳制
  → new DeviceManager(_config)   按开关选 Mock/真实/null 装配四个驱动
  → DeviceManager.Start()
      → _barometerReader.Connect(_config)   气压表串口（必须成功，否则整机不可用）
      → _ioController.Connect(_config)      IO耦合器 TCP（可选，失败只告警）
      → _fanController.Connect(_config)     送风机 TCP（可选，失败只告警）
      → 采集定时器启动（默认 1 秒一轮）
      → 先报一次连接事件，再采首轮（启动路径禁耗时阻塞，扫码枪 WMI 放线程池并行）
```

采集循环里：读 72 台压力 → 读 DI/DO → 叠加工位信息 → 跑状态机 → 触发 `OnBatchDataUpdated` → 主窗刷新画布。送风机走**独立的约 2 秒定时器**，不阻塞气压表采集。

### 4.2 气压表：Modbus RTU（`ModbusRtuBarometerReader`）

连接参数（缺省在 `DeviceConfig`）：串口 `PortName=COM9`（仅兜底）、波特率 19200、8 数据位、停止位 `1`（存字符串，`15`=1.5，`2`=2）、校验 `None`、读写超时各 1000ms。

**串口三级候选**（`BuildCandidatePorts`，按顺序试，第一个打开成功的即用）：

1. 磁盘缓存 `BarometerPort.cache`（exe 目录，一行 `COMx`，"工控机记忆"）；
2. 配置的 `PortName`；
3. WMI 搜 CH340（`SerialPortHelper`：描述含 CH340 **且** `VID_1A86/PID_7523`，双条件缺一不可）。

连上就把实际串口写回缓存，下次优先。读压力：`ReadInputRegisters(从站=deviceId, 起始=0x0001, 读2个)`，功能码 **0x04**。换算收拢在两个纯函数里（可单测）：

```csharp
static decimal ConvertRawToPressureKPa(short rawSigned, int decimalPlaces, decimal scale);
// 压力 = (short)原始值 / 10^小数位 × 缩放。例：0xFFCE → (short)-50 → -50/10 = -5.0kPa
static long ConvertThresholdToRegister(decimal thresholdValue, int decimalPlaces);
// 写阈值逆运算：-5.0×10 = -50 → (ushort)0xFFCE，设备按有符号解释
```

写阈值：`WriteSingleRegister(从站, 0x0010, 值)`，功能码 **0x06**，批量写每台后 `Sleep(50)` 给 RS485 安静时间。

**两种阈值千万别混**（新人必错）：`AlarmPressureThresholdKPa`（软件判报警用，kPa，**只放内存比较，不写设备**）≠ 设备阈值（写气压表 0x0010 寄存器，单位跟压力读数一致）。公共参数窗"批量写阈值"写的是后者。

新手坑 Top 5：

1. 忘 `(short)` 强转：0xFFCE 会变成 65534，负压反号。
2. 用设备返回的 0x0002 小数位：现场近半数台返回 0，会差 10 倍。统一用配置 `BarometerDefaultDecimalPlaces=1`。
3. 并发读串口：`SerialPort` + NModbus Master 非线程安全，所有收发必须 `lock(_syncRoot)`；RS485 半双工 72 台必须串行一问一答，禁并行。
4. 单台超时误判整线掉线：只有端口级异常（串口被拔/句柄失效）才置整线断开；从站超时只是"这台离线"。
5. `ReadAllData` 串口断开时返回**全 null 数组**（不是空数组）——故意的，让 `DeviceManager` 累失败次数触发"通讯故障关阀断电"兜底，别"优化"掉。

### 4.3 IO 耦合器：Modbus TCP（`ModbusTcpIoController` + `IoMapBuilder`）

连接参数：`192.168.1.20:502`，从站 1，DI 起点 `0x1000`（功能码 0x04），DO 起点 `0x2000`（读 0x03 / 写 0x06），收发超时 3000ms。连接用 `BeginConnect + WaitOne` 手动超时——因为 `TcpClient.Connect` 不受 Timeout 约束，IP 配错会卡启动约 20 秒。

**编号体系**（理解映射的关键）：程序内部用**十进制连续编号**，`IoMapBuilder` 翻译成三菱**八进制物理地址**（注意八进制没有 8 和 9：X007 后面是 X010）：

- 输入 1~80：1~72 = 72 台气压表报警触点 DI，73~80 预留。`X地址 = 八进制(编号-1)`，如 9 号输入 → X010。
- 输出 81~240：`80+deviceId` = 真空阀（81~152），`80+72+deviceId` = 载台电源（153~224），225~240 预留。
- 打包规则：**16 点一个寄存器**，`寄存器 = 起始 + 位序号/16`，`bit = 位序号%16`。

**读-改-写铁律**：0x2004 低字节是阀 65~72、高字节是电源 1~8，两个业务共用一个字。单点写必须"读出整字 → 改 1 个 bit → 写回整字"，**整字直写会误伤另一个业务**（比如关电源时把 65~72 号阀连带关了）。"载台全关"也只清高字节、保留低字节。

**备用通道映射**：某个 DO 通道烧了不断线？开 `IoBackupChannelMappingEnabled`，映射 `源寄存器@源通道 → 目标寄存器@目标通道`（全十六进制，通道只认 0x00~0x0F）。读/写/批量读自动重定向；非法目标保持原通道（绝不写坏掩码）。V1.81 起不用手写映射字符串，通讯测试窗里右键点可视化连线，保存走设置表同一条路即时生效。

NPN/PNP 现场差异：灯亮但软件读 OFF（或反过来），把 `InvertInputs` / `InvertOutputs` 置 true，先看灯再改配置，别改代码。

### 4.4 送风机：Modbus TCP 端口 50000（`FanControllerClient`）

最大特点：**它是可选设备**，连不上不影响整机启动和测试（只有"无温控"告警）。记住三个数：端口 **50000**（502 是 IO 耦合器的，别混）、一次读 6 个寄存器（0x0000~0x0005，功能码 0x03）、温度/湿度除以 100。

| 寄存器 | 说明 |
| :--- | :--- |
| 0x0000 | 组合状态，忽略 |
| 0x0001 | 写 0x0003=定值启动，写 0x0002=定值停止（功能码 0x06） |
| 0x0002 / 0x0003 | 当前温度 / 湿度（÷100） |
| 0x0004 / 0x0005 | 温度 / 湿度设定值（÷100） |

状态枚举 4 值：0x0000 程式停止 / 0x0001 程式运行中 / 0x0002 定值停止 / 0x0003 定值启动，UI 用显式 switch 转中文，别 `ToString()`（会显示裸数字）。

**IP 自动识别**：候选顺序 = 上次成功的 `FanLastIp.cache` → 配置主 IP → 候选列表 `FanIpCandidates`。设备换 IP 会自动找到并更新缓存。

**生命周期**（`DeviceManager.UpdateFanLifecycle`，72 台共用一台风机，不能随某台停）：首台进入测试 → 启动一次；末台退出测试 → 停机。"只下发一次"靠状态记忆，重复调用不重复发命令。主界面没有手动启停按钮（以前有，因"手动停了会被采集循环立即重启"而删除，属误导性操作），维护停机请用"关于 → 送风机测试"。

### 4.5 扫码枪：虚拟串口 + WMI（`ScannerService`）

Honeywell Xenon 1902，115200 波特率，ASCII 文本行协议（条码 + 回车换行）。核心难点不在读数据，在**判定"枪还在不在"**：

- `SerialPort.GetPortNames()` 看的是注册表残留，拔了线还在——**不可靠**。
- 拔线时 `ReadExisting()` 对多数芯片静默返回空、不抛异常——**不可靠**。
- 唯一可靠的是 **WMI 动态搜 PnP 节点**（`Win32_PnPEntity` 按关键词 `Xenon 1902` 找，拔出节点即消失）+ 监听 `WM_DEVICECHANGE` 热插拔消息 + 每约 12 秒关句柄重搜兜底"鬼设备"残留。

三条铁律：① `ScannerService` 必须在 **UI 线程构造和 Start**（内部 WinForms Timer + 隐形窗口收系统消息，依赖消息泵；耗时 WMI 已内部转线程池，不卡界面）；② `WM_DEVICECHANGE` 处理中只关句柄，WMI 重搜排到后台（否则报 `RPC_E_CANTCALLOUT_ININPUTSYNCCALL`）；③ 日志只记边沿，`ScannerDebugLog` 发货保持关闭。

扫码事件 `OnBarcodeScanned` 已经 Post 到 UI 线程，录入批号窗和 ID 绑定窗直接订阅即可，扫码自动填框。枪没连上时 `TryReconnectNow()` 有界等 3 秒，连不上就先手输，后台连上自动翻绿——**永不因为扫码枪拦住生产**。

### 4.6 两扇测试窗：复用连接，不自建（`CommunicationTestForm` / `FanTestForm`）

现场调试入口："关于 → 通讯测试 / 送风机测试"（技术员及以上）。构造只收 `DeviceManager`，**不持有任何 TcpClient/串口**：

- IO 测试窗：三页灯按钮（真空阀 / 载台电源 / 预留点位，点位来自 `IoMapBuilder`）+ 一键遍历跑马灯 + 右键端口映射。读写经 `DeviceManager.ReadHoldingRegisters/WriteSingleRegister`，状态刷新定时器只读 `IsIoConnected`（不发报文）。
- 风机测试窗：只读显示配置 IP（换设备改 `App.config`），状态读 2 秒轮询缓存，控制调 `StartFan/StopFan`。
- 关窗必须拦住在途后台任务（`_closed` 标志 + `IsDisposed` 检查），否则"关了窗还在动设备"。

### 4.7 新增一种设备（如电流表、PLC）的标准步骤

1. `Interfaces/` 新建 `IXxx.cs`，照抄第 3.3 节六件套。

## 5. 主界面与工作站微调：自绘画布完全指南

> 这是二次开发改得最多的地方，也是坑最多的地方。请按顺序读完 5.1→5.5 再动手，5.6 是 SunnyUI 保命清单，5.7 是加配置项的清单。

### 5.1 先建立正确的心智模型：72 站 = 1 个控件，不是 72 个

`Views/WorkstationGridView.cs` 是一个 `UserControl`，72 个工位面板是它在 `OnPaint` 里**一笔一笔画出来的**（`FillRectangle` 画底、`DrawText` 写字），不是 72 个 Panel 控件。这样做的原因：72 个真控件每秒刷新一次，WinForms 消息队列直接爆炸；自绘一帧只重绘可见区，稳如泰山。

数据流（记住这个链条，改显示问题顺着它查）：

```
DeviceManager 1秒一轮 → MainForm.DeviceManager_OnBatchDataUpdated
  → _gridView.UpdateAll(BarometerData[])   只写内存 + Invalidate() 标脏，不画
    → OnPaint(e)   只画 e.ClipRectangle 可见行列的面板
```

`ApplyData` 把业务数据翻译成"怎么画"（文本、开关、颜色），`DrawPanel` 按固定顺序画 7 步：底色 → 编号 → 上电/真空块 → 压力值框 → SN/配方/延时/烧屏 → 设置按钮 → 选中框。**`OnPaint` 里禁止量字、禁止拼字符串**（字高全在布局时量好缓存，画时只读），否则 72 面板每秒全量拼串，帧率直接掉沟里。

当前面板长什么样（96DPI 逻辑像素，关电流时 204×144，见 `WorkstationGridView.cs` 头部 ASCII 图——**改界面必须同步改那张图**）：

```
第一行：NO.x编号 + 上电块 + 真空块 + 选中框（同行，省纵向空间）
下面：压力值框 / SN / 配方 / 延时 / 烧屏 / 设置按钮
```

### 5.2 面板布局锚定系统：改坐标的唯一正确姿势

面板里每个元素的位置**不许写死绝对坐标**，必须用"锚定"声明它和"面板边缘"或"其他元素"的相对关系。所有锚定字段在 `Models/PanelLayoutConfig.cs`（类头注释有全表和依赖链，改坐标前必读），解析顺序铁律 `ResolveAnchors` 三步：

```
① 面板边缘锚定（贴右缘 RightMargin / 贴顶 TopMargin / 贴底 BottomMargin）
② 元素间锚定（下链：设置按钮→配方；上链：选中框→真空→SN→…→延时）
③ 标签锚定（标签跟着值框走，垂直居中）
```

顺序错一位就会读到目标的旧值导致错位。几个常用锚定语义：

| 写法 | 意思 |
| :--- | :--- |
| `RightMargin=9` | 右缘距面板右缘 9px，面板加宽自动跟随 |
| `RightToLeftAlignTo="SelectBox", Gap=4` | 我的右缘贴 SelectBox 的左缘，留 4px 缝 |
| `LeftAlignTo="SNValue" + RightToLeftAlignTo="VacuumOpen"` | **双端锚定**：左右各贴一个，宽度自动推导 |
| `BottomMargin=7` | 贴底，面板加高自动下移 |
| `VerticalAlignTo="VacuumOpen"` | 和真空块同 Y 同高（同行等高） |

**改坐标通用五步**：①读类头注释定该元素当前锚定 → ②定范围（单元素/整列/面板尺寸）→ ③只改锚定字段、不手算终值 → ④跑回归断言终值 → ⑤同步 `WorkstationGridView` 头部 ASCII 图。

三个最常见的改法：

- **只动一个元素**（如把烧屏时间框右移）：先删掉它的列锚定（`LeftAlignTo`），改用绝对 X，否则下次解析会被锚定覆盖回去——"改了不生效"就是这个坑。并且先算会不会撞到别的元素（锚定强迫你在改前算清连带，这正是它的价值）。
- **整列一起动**：不动每个框，改列基准（如按钮的 `RightMargin`），全列自动跟随。
- **面板加高/加宽**：只改 `PanelInnerHeight` / `PanelInnerWidth`，贴底的按钮和下链自动下移/右移，上链不动，缝隙吸收差值。**禁止在代码里手写 144/152 这类字面量**，行高/画布/命中一律走 `GetEffectiveInnerHeight()` / `GetEffectiveRowHeight()`。

互斥规则：同一方向只配一种锚定（如 X 方向 `RightMargin` / `RightAlignTo` / `LeftAlignTo` 只配其一，双端锚定除外）。配冲突不会报错，靠目检 + 回归抓。

### 5.3 缩放 / 字体 / DPI 三件套

72 站永远一屏铺满（无滚动条），靠 `ComputeFitZoom` 纯函数：`zoomX=可用宽/内容宽、zoomY=可用高/内容高` 独立计算，面板允许宽扁拉伸。绘制和命中必须用 `ScaledX` / `ScaledY` **分流**（禁止合一，宽扁拉伸下点选会错位，编译器会把漏改的旧调用揪出来）。

字体三规则：①取窄边缩放（`z=min(zoomX,zoomY)`，面板拉扁字不变形）；②下限 4pt（小屏跟随缩小不挤叠）；③正文一律加粗（4~5pt 常规体发虚，加粗才看得清）。行全选列的竖排大字字号 = 正文×`RowSelectFontScale`。

DPI 三规则：①坐标全是 96DPI 逻辑像素，内部手动乘 `_dpiScale = CreateGraphics().DpiX / 96`；②取 DPI 用 `CreateGraphics().DpiX`，**别用 `DeviceDpi`**（句柄刚创建时它谎报 96）；③**禁用 `Graphics.ScaleTransform`**（`TextRenderer` 走 GDI 不认坐标变换，会错位叠字）。

GDI 资源：跟主题走的画笔在 `RebuildThemeBrushes` 重建，控件销毁时在 `Dispose` 释放（只覆盖不释放 = 换主题不漏、关控件漏）。

### 5.4 命中检测：先问"缝隙归谁"

鼠标点选是"行列整除"算出第几格，但面板之间有缝隙——整除会把缝隙算进上一格，点缝隙误翻选上一个面板。铁律：**`TryHitPanel` 算出格子后，必须验落点在内容矩形内，缝隙一律不命中**（悬停提示同步消失）。以后凡是"整除分格"的命中逻辑，先问"缝隙归谁"。

点选行为（单击即切换，无需长按）：点设置按钮 → 按编号直开该工位设置窗（不看选中了几个）；点选中框/空白 → 翻选；行最右"全选"按钮 → 整行切换。选中框恒正方形，绘制和命中用同一函数出矩形（同源才不会"看着选中了、点着没选中"）。

### 5.5 MainForm 布局常量：顶栏锁死 30，右栏按比例

主窗布局纯代码固定（`ApplyHomeLayout`）：顶栏 30px（锁死，不可调，和 9pt 字/18px 按钮互相咬合）/ 中间工位区 / 右侧操作区 / 状态栏 30px。右侧宽度 = 父容器宽×`RightPanelRatio`(0.16)，上下限 200~240 钳制（`ComputeRightPanelWidth` 纯函数，可单测）；分栏分隔条锁死不可拖，比例永远按窗口走。左侧有 640px 底线保护（`ClampRightPanelWidthForWorkstation`），小屏上右侧会被压回来。

无系统标题栏：`ShowTitle=false` 藏掉 Sunny 标题，最小化/最大化/关闭三个按钮用 GDI 线条自绘进顶栏最右（**禁用 emoji/Unicode 符号**，老工控机字体回退显示方块）。窗口拖动/边缘缩放在 `WndProc` 里处理：双击消息必须拦在 `base` 之前（否则系统切一次、你再切一次，两次抵消）；边缘 6px 回缩放码，顶栏非按钮区回拖动码。

项目切换热更（`ReloadActiveProject` 八步，免重启）：在测复查 → 暂停采集 → 重读配置 → `CopyFrom` 就地换血（`_config` 是 readonly 引用，**禁止换引用**，服务侧拿的还是旧对象）→ 工位缓存 `Reload` → 清项目态（禁调 `StopAll`，那是写 IO 全 OFF 的急停语义）→ 重读配方 → 重布局 + 刷帧。硬件连接（串口/TCP/扫码枪跟机器）不断。

### 5.6 SunnyUI 保命清单（新窗体/改界面前读一遍）

1. 控件对照切：Form→UIForm / Label→UILabel / Button→UIButton / TextBox→UITextBox / ComboBox→UIComboBox / GroupBox→UIGroupBox / DataGridView→UIDataGridView；日志框/CheckBox/NumericUpDown/ListBox/状态条保持原生。
2. 语义色经 `Style=Custom + FillColor/RectColor`（原生 BackColor 在自绘按钮上画不出来）。
3. `UILabel` 缺省 `AutoSize=false`（和原生反直觉！），AutoSize 列的填充子必须显式打开。
4. `UITextBox` 没有 `ScrollBars/WordWrap`（用 `ShowScrollBar/WordWarp`）；下拉框样式枚举叫 `UIDropDownStyle`。
5. `is Button` 认不出 UIButton/UITextBox/UIComboBox（不是原生子类），类型判断按类型名走；按钮改色走 `ThemeManager.ApplyButtonColors`。
6. UIForm 自绘标题占 35px 客户区：藏标题用 `ShowTitle=false` + 顶 Padding 清零，别去改控件 Y（Designer 的 Y 就是运行 Y）。
7. 新窗体打开前调一次 `ThemeManager.ApplyTo(form)`；**按钮颜色一律不动**（全是业务语义色，换肤自动豁免）。
8. 动态重建控件先逐个 `Dispose()` 再 `Clear()`（走 `ControlDisposeHelper.DisposeAllAndClear`），否则孤儿控件进终结器线程跨线程崩溃。
9. `InitializeComponent` 方法体内禁写注释（VS 重写整段再生会全删）；手写 Designer 与 VS 重写不一致时，以 VS 版为基准接受。
10. 所有 `.cs` 必须 UTF-8 编码，否则设计器报"无法设计基类"。

### 5.7 SettingsForm：新增一个配置项要改的全部位置（清单）

设置表是"一个表格 + 按 key 分发编辑器 + 统一校验 + 统一保存"。`CreateValueCell` 按 key 分发（布尔/串口/波特率/下拉/数字/文本/弹窗编辑），`ValidateValue` 独立校验，`PersistChanges` 统一落盘（工艺策略窗走的是**同一条**保存路，落盘语义只有一份）。

- **普通机器项**（布尔/数字/串口）：①`DeviceConfig` 属性 → ②`App.config` key（含中文注释）→ ③`MainForm` 读取（含归一化与钳制）→ ④`SettingsForm` 的 `_boolKeys` **和** `ValidateValue` 布尔分支（**两个名单都要进**，只进一个会导致脏值能存）+ `_descriptions` + `_categories` → ⑤回归"布尔键一致"变绿。
- **枚举型策略项**：①`PolicyEnums` 枚举（0 值 = 现状行为，**只能追加、禁改顺序**）→ ②`DeviceConfig` 属性 → ③`ProjectPolicyStore.PolicyKeys`（**唯一名单**）→ ④`EnumOptions` 下拉（中文显示/英文存储）→ ⑤`App.config` 机器缺省 → ⑥`MainForm` 读取（非法兜底现状）→ ⑦`SettingsForm` 描述/分类/校验/下拉 → ⑧回归"三处同步锁"变绿。
- 数字 + 语义开关二合一（如"真空超时 0=关闭"）：走可手输下拉，不走数字微调框；`ValidateValue` 独立分支锁范围（含 0、拦负数）。
- tooltip 说明必须写清"现状是什么 / 改了会怎样"，超 40 字走 `WrapTooltip` 换行；跨窗体复用说明只走 `SettingsForm.GetDescription`（禁各写一份文案）。

## 6. 业务子系统：状态机、数据、权限、外设

### 6.1 老化三阶段状态机（`DeviceManager` + `AgingSequencer`）

单台流程：**Vacuuming 抽真空 → Aging 老化计时 → Completed 待取料**，外加空闲/故障态。

```
[准备] 录入批号 → 绑定工位↔SN → 设配方（延时/烧屏时长/负压阈值/显示模式随配方下发）
[启动] 只开真空阀 + 送风机定值启动；任务参数（时长/延时/阈值/SN/配方）此刻定格，快照落盘
[抽真空] 等"真空到位"且"距开阀 ≥ 配方延时时间"两者满足；延时=0 则阀电同开直接计时
        超时（默认15s，设0=关闭不限时等）始终不到位 → 真空建立失败报警：关阀断电标故障，全程不带电
[上电] 条件满足自动载台上电 → 进入老化计时（计时起点=上电时刻；上电写失败滚回抽真空，不许带病计时）
[老化] 时长=配方"烧屏时间"（>0），否则回退全局配置（0=不限时长靠人工停）
[完成] 到时自动下电+关阀 → "已完成·待取料"（蓝面板）→ 记 PASS（待判定策略则记"待判定"，下料时人工录 PASS/FAIL）
[停止] 手动停止=中止（回空闲，不计判定）；末台停时送风机自动停
[急停] 全关阀+全断电+停风机+清快照（带防误触确认；IO 写失败保持原态可重试，判定只举旗不动状态）
[断电恢复] 重启发现 TestSession.json 快照 → 弹窗选"整台重测"或"放弃并安全关阀断电"
```

**定格语义**：启动瞬间的参数定格，中途改配方/重绑 SN 只对新启动生效（批量/工位窗在测下发会提示"仅对新启动生效"）。无任务时阈值回全局。

**报警边沿联动**：压力越限 / 真空建立超时 / 通讯失联（连续 3 次读不到）/ DI 触点（可选）→ 进入边沿触发**一次**（不是每轮重复）→ 关该台阀 + 断电 + 标故障 + 写 CSV。`ClassifyAlarm` 分三支：L2 全关先压 → 确认窗内超时 → 越限（真空类）→ DI（非真空类）。结果分类：产品 FAIL / 装夹异常（真空责任策略）/ 设备异常（通讯失联）。**先写后清**：IO 写失败时保持原态、可重试，绝不清了状态但没写下去（软硬分叉）。

### 6.2 配方 / 工位 / 策略 / 项目四件套（数据流）

- **配方**（`RecipeConfig` + `RecipeStorage`，跟项目走）：字段 = 名称/负压值/显示模式/延时/烧屏时长/极限温度。三个录入窗（配方管理/批量/工位设置）→ `SetStationRecipe` 下发 → `StationInfo` → 叠加到面板数据。加字段必须走完这条链，漏一处就是"存了用不上"。配方名只许下拉选（禁手输，防错名静默回退全局配置 = 串配方）；`SetStationRecipe` 只认 `null` = 回退全局，下发 0 就是定格 0。
- **工位**（`StationInfo` 内存态 + `StationSettingsCache` 落盘回填态，跟项目走）：SN/配方/延时/负压/显示模式。ID 绑定窗写 SN，工位设置窗写全套。切项目必须 `Reload()`，否则内存还是旧项目的。
- **策略**（`PolicyEnums` 9 个枚举 + `ProjectPolicyStore` + `PolicyPresets` A/B/C/D 预置）：0 值恒为现状行为。预置 A=常用/B=标准/C=宽松/D=严格，一键套用；下拉末项"自定义"是独立槽（初始 = A 快照，改后各存各的）；导入一律进自定义槽，A/B/C/D 代码写死覆盖不了。工艺策略窗拓扑画死（物理锁死，防客户删掉安全联锁），节点只挂真实 key，保存走设置表同一条路。
- **项目**（`ProjectProfile`）：`Projects/<项目>/` 目录 + `.project` 哨兵。新建/切换/删除，名字先验防路径穿越。切换只写指针，换装走主窗八步热更（第 5.5 节），在测禁切。

### 6.3 用户权限与 dev（`UserManager` + `PasswordHasher`）

三角色：操作员 / 技术员 / 管理员（权限按等级 `>=` 比）。`Users.json` 存 PBKDF2-SHA256 哈希（随机盐 + 10 万次迭代，`PBKDF2$迭代$盐$哈希` 自描述格式），**明文绝不落盘**，也不入库（gitignore）。对外只吐副本（防拿引用绕过校验改密码）。

隐藏最高权限 `dev / dev123`：走"用户权限 → 管理员"登录框输入即进，界面无提示。dev 可删改业务管理员；`dev` 名（含大小写变体）注册/改名一律回"该账号名不可用"；dev 自身禁改名禁删除；登录下拉永不出现 dev。记住密码走 DPAPI 加密（禁 Base64）。

### 6.4 MES 上报与规则表达式

- **MES**（`MesMapping` + `MesReporter` + `MesCrypto`）：触发器 Start/Complete/Alarm/UnloadJudge 四事件，后台 POST JSON（鉴权/重试/离线缓存 `MesQueue.json`，失败**永不阻断生产**）。映射 vocabulary（字段名/触发器名）唯一出处是 `MesMapping` 纯函数，设置窗/上报器/用例三方共用；脏输入保存时拦、上报时跳过。密钥（token/密码）内存明文、文件 DPAPI 密文。开关开了没配地址，保存即拦。
- **规则**（`RuleExpr` 手写递归下降 + `RuleEngine` 执行器）：变量冻结 13 个（`pressure/temp/tempset/hum/device/delaysecs/vacsecs/agesecs/duration/threshold/di0/hour/current`），加变量要同步四处。NaN 比较恒 false（fail-safe）；`&&` `||` 短路；规则**只能加严不能松绑**（自定义报警只多报、完成表达式 OR 只能提前、内置联锁动不了）。规则格式 `名称|表达式|持续秒`，表达式里允许 `||`（解析时枚举切分点取首个全合法组合）。持续计时状态变迁（启动/复位/停止/急停）必须调 `ResetStation`，否则旧计时带到新任务。

### 6.5 日志、快照、水印、激活

- 三类日志全在 exe 目录 `Logs/`：`TestLog_yyyyMMdd.csv`（结构化事件：时间/批号/SN/配方/工位/事件/结果/详情/压力/温度/电流；只有完成/判定/报警三类有结果值）、`AppLog_yyyyMMdd.log`（主窗 LOG 框逐行落盘）、`Crash_*.log`（一崩一文件，含版本水印 + 全堆栈，请客户发回此文件，崩溃处理路径绝不抛异常）。
- 快照 `TestSession.json`：启动/上电/完成/停止/复位后保存，急停/放弃/全结束清除，正常退出不删（重启仍问恢复）。
- 水印 `BuildWatermark`：主窗构造首行写版本水印（对外版本 + exe 构建时间 + 混淆标记 + 进程位数 + OS），远程排错先看这行定版本。发版改 `ReleaseLabel`，与 CHANGELOG 顶部同值。
- 激活（`SoftwareActivation` + `SoftActivation` 窗，与 HJVision 同源同口径，同一套《获取激活码》工具通用）：CPU 序列号 + MD5 前 15 字节 hex（30 字符）。设备码恒定（历史原因，**不许"顺手修"**，否则两边对不上）。存 `MainSetting.ini [RunHash]` 双键（gitignore）。无试用、无启动闸：新机每小时提醒一次，不阻断启动、不拦生产，只置灰用户权限入口；激活成功关窗即解灰。判定逻辑只进纯函数，Timer 与激活窗共用。

## 9. 常见问题排查速查

| 现象 | 先查什么 |
