> 本项目全部硬件通讯的**寄存器映射 / 换算 / 坑点 / 排障**汇总，改动协议时同步更新本文件。
> 测试入口：主程序"关于"菜单 → **通讯测试**（IO 耦合器）/ **送风机测试**。

## 1. 整体链路

1. 上位机按 `CollectInterval`（默认 1s）轮询 72 台气压表压力（RTU）；IO 耦合器 DI/DO 随采集轮询；送风机独立 2s 轮询。
   启动顺序（V1.100）：连各设备→立即上报连接状态→首轮 72 台采集放后台（离线台逐台超时可达分钟级，不再拖住界面）；
   扫码枪 WMI 识别与采集并行，LOG 首轮行直接给出"在线 X/Y＋离线台号＋耗时"。
   离线加速（V1.103）：轮询读零重试（`Retries=0`，离线台≈1 个超时/台，24 台离线首轮≈24 秒；
   NModbus 缺省 3 次重试时约 5 秒/台、24 台≈2 分钟）＋逐台进度（`SingleReadCallback`→`OnScanProgress`
   400ms 节流，状态栏"扫描中 M/N"实时爬，不等整轮）＋在线窗口按实测耗时自适应（快轮询恒 10 秒）。
   写阈值保留重试（低频人工操作）。
2. 软件用 `AlarmPressureThresholdKPa`（默认 -5kPa）判报警；总开关 `PressureAlarmEnabled`（默认 true=开，跟项目走，预置A默认关闭）关掉后阈值越限与真空建立超时全不报、负压阀保持常开（DI触点/通讯失联/自定义规则不受影响）；最高级 `MuteAllAlarms`（2.0.0，默认关）开后阈值/超时/DI/失联/规则/超温联停全不报（四预置默认全关，只走手动/自定义）；真空异常蜂鸣开关 `VacuumAlarmBuzzerEnabled`（2.0.6，默认 true，跟项目走）只管响不响，不影响报警判定。策略层最高优先级（机器缺省→项目策略叠加，项目赢；没存过的管辖项缺省按A）。
3. 报警**进入边沿**触发一次联动：关该台真空电磁阀 + 断载台上电 + 标故障（`DeviceManager.HandleAlarm`）。
4. 老化三阶段状态机：启动开真空阀（延时>0 只开阀，延时=0 阀电同开直接计时） → 真空到位且配方延时时间到→自动载台上电（超时报警断电，延时>0 全程不带电；超时设 0=关闭：不限时等，不判建立超时，只靠老化失压报警+人工停止）→ 首台在测即自动定值启动送风机 → 按配方计时 → 到时自动下电关阀标"已完成·待取料" / 手动停止=中止 / 急停全停；**末台退出在测且没有未复位报警**才自动停止送风机（省电）——报警台退台后炉子还在发热，报警未复位前保持送风，避免单台故障扩大成过温事故。
   - 主界面没有手动开阀/手动启停风机按钮（游离态误导，已删）；单点点动用"通讯测试(IO)"，风机维护用"送风机测试"。
    - V1.67 策略影响执行（缺省=下述现状）：真空类报警可切"装夹异常"（VacuumFailKind）、完成可标"待判定"（CompletionJudgePolicy，下料人工录）、断电可续跑（PowerLossPolicy）、老化中失压可只记不停（AgingPressureLossPolicy）、完成可蜂鸣/泄压（CompletionAction）。寄存器与协议本身无变化。
    - V1.73 破空阀开关（VentValveEnabled，默认false=本机无阀）：关则手动破空按钮隐藏、泄压组合保存即拦、执行只记日志跳过；有阀项目打开+配点位后泄压真写DO。寄存器与协议本身无变化。
    - 2.0.3 超温蜂鸣器（新现场需求：冷却送风机超温触发蜂鸣报警）：接 IO 耦合器 DO 输出点，点位
      `FanBuzzerDoPoint`（默认0=未接，**不写任何通道**；系统设置"老化测试业务"下拉只列**空余的预留输出点**，
      被破空阀占用的点不进选项，选中即生效，工艺策略窗已不再提供该项）；
      方式 `FanBuzzerMode` 三档（Level=持续响、报警解除自动停（默认；超温源即回温）/Pulse=短鸣约3秒/Intermittent=响2秒停2秒循环）；
      触发阈值共用超温告警上限 `FanTempAlarmLimitC`（0=不启用则蜂鸣器也不工作），"报警全关"压制时跟着哑，
      与联停开关互不牵制；保存侧并入破空阀同一条工位区间碰撞校验（写成工位阀/电编号保存即拦）。
      写 IO 走既有耦合器输出（读-改-写单 bit、备用通道映射适用），寄存器与协议本身无变化。
    - 2.0.6 真空异常蜂鸣（客户需求：超温/真空异常只提醒，不关送风和压缩机）：`VacuumAlarmBuzzerEnabled`
      （默认 true，跟项目走）让真空类报警（老化中压力越限 / 真空建立超时 / 失压保持运行）也触发**同一个**
      蜂鸣器 DO 点；超温与真空两路源合并判定（任一路未解除就继续响，两路都解除才停），
      `MuteAllAlarms` 照旧压制全部。真空报警本身仍只退故障那一台（关该台阀+断电），
      **不联停整线**；送风机改为"在测 或 有未复位报警"保持运行，人工复位/急停后才停。
      未接蜂鸣器（`FanBuzzerDoPoint=0`）或风机未启用时只记日志，不写任何通道。寄存器与协议本身无变化。
   - V1.69 规则影响执行（缺省=下述现状）：自定义报警规则（成立即报警记FAIL，与内置同一边沿）、完成表达式（成立即提前完成，只能提前）、跳过抽真空（启动即上电+压力豁免）。寄存器与协议本身无变化。
5. 编排核心：`DeviceManager.cs`。

## 2. 气压表（Modbus RTU）

### 2.1 协议要点
- 一主多从：主站=上位机，72 台气压表=从站，**slaveId = deviceId（1~72）**。
- RTU 帧带 CRC；`SerialPort`/NModbus 主站**不支持并发**，生产实现用 `_syncRoot` 锁串行化。
  【V1.103 强调】串行不是实现偷懒，是 RS485 半双工共享总线的物理约束（同一时刻只能一问一答，
  并行发请求会帧交叉 CRC 错）；要真并行只能硬件改多总线（多路 RS485 分段、每段独立 COM 口），
  纯软件层面只能压"每台等待"（轮询零重试）和"整轮才显示"（逐台进度）两头。

### 2.2 寄存器（实测定论）

| 寄存器 | 类型 | 功能码 | 含义 |
| :--- | :--- | :--- | :--- |
| `0x0001` | Input Register | 0x04 | 压力原始值（**按有符号 short** 解释，支持负压） |
| `0x0002` | Input Register | 0x04 | 小数位数（0~4；**实测 47/72 台返回 0 不可靠**，生产统一用配置 `BarometerDefaultDecimalPlaces`=1） |
| `0x0010` | Holding Register | 0x06 | 设备阈值（写气压表内部硬件报警点） |

### 2.3 换算
- **压力**：`(short)raw / 10^小数位`（kPa）。示例：0x0001=0xFFCE → -50，小数位 1 → -5.0。**必须显式 (short) 强转**，否则 0xFFFE 被当 65534。
- **阈值**：`寄存器值 = (ushort)round(阈值浮点 × 10^小数位)`；负值按补码回绕（设备按有符号解释）。示例：-5.0、小数位 1 → 0xFFCE。

### 2.4 设备阈值写入
- 入口：`DeviceManager.SetBarometerThreshold(台号, 值)` 单台 / `SetAllBarometerThresholds(值)` 批量（返回失败名单，逐台失败不中断）。
- ⚠️ 单位是**设备单位**（与压力读数同单位同小数位），**不是** -5kPa 软件报警阈值；按说明书确认后再写。
- 批量写 72 台较慢，应在后台线程执行；写超时通常=该台掉线/损坏（先扫描定位）。

### 2.5 排障速查

| 现象 | 排查方向 |
| :--- | :--- |
| 未找到 CH340 | USB 未插/驱动未装（VID_1A86/PID_7523 才认） |
| Access denied | 串口被其它软件占用 |
| 读失败/重试仍失败 | 从站地址错、波特率不符、A/B 反了、共地缺失 |
| 配错不报错但连不上 | 启动加载对波特率/数据位/串口超时做钳制（气压表+扫码枪共 6 项），越界回退合法值并写 `Debug` 日志；先看日志确认是否被钳制 |
| 数值巨大正数 | 没做 (short) 强转，或小数位/缩放配错 |
| 批量写某台一直超时 | **该台设备问题**（掉线/断电/地址拨错/损坏）；扫描 `Logs\BarometerScan_*.csv` 定位，多扫几遍区分"永久离线"vs"间歇掉线" |
| 在线数少于上电数（如 72 台只在线 48 台） | 看启动 LOG 首轮诊断行（V1.100 起直接报出离线台号+耗时）：离线集中在尾段多为从站地址拨错/接线断，
尾段之后全灭查该段 RS485 接线与终端电阻；散布多为总线负载超限（加中继器）/供电不足。软件无台数上限，少了就是没回包 |

## 3. IO 耦合器（GX-CL140 Modbus TCP）

### 3.1 硬件要点
- **SP 与 FP 都要供 24V**（SP=耦合器本体，FP=IO 模块回路；FP 断则 AL 红灯闪）。
- PC 网卡与耦合器同网段；网线插紧（**ST 闪绿但不通 = 接触不良**）。
- 指示灯：SP/SYS/AL/ST 绿常亮为正常；SYS 红闪=等网络；长按复位键>6s 恢复出厂。
- 现场规模 80DI/160DO，业务用 72DI/144DO（多出的 8DI+16DO 预留）。

### 3.2 寄存器 ↔ 通道（bit0=第1路，bit15=第16路）

| 类型 | 起始地址 | 功能码 | 说明 |
| :--- | :--- | :--- | :--- |
| DI 输入 | 0x1000 | 0x04 | 0x1000~0x1004 = DI 1~80（对应 X000~X107；65~72 气压表，73~80 预留） |
| DO 输出 | 0x2000 | 读 0x03 / 写 0x06 | 0x2000~0x2009 = DO 1~160 |

**DO 详细分布**（⚠️ 0x2004 的低/高字节分属两个业务，**单点写必须读-改-写**）：

| 寄存器 | 低字节(bit0~7) | 高字节(bit8~15) | 业务 |
| :--- | :--- | :--- | :--- |
| 0x2000~0x2003 | — | — | 真空电磁阀 1~64（Y000~Y077） |
| 0x2004 | 电磁阀 65~72（Y100~Y107） | **载台上电 1~8（Y110~Y117）** | 混合 |
| 0x2005 | 载台上电 9~16（Y120~Y127） | 载台上电 17~24（Y130~Y137） | 载台上电 |
| 0x2006 | 25~32（Y140~Y147） | 33~40（Y150~Y157） | 载台上电 |
| 0x2007 | 41~48（Y160~Y167） | 49~56（Y170~Y177） | 载台上电 |
| 0x2008 | 57~64（Y200~Y207） | 65~72（Y210~Y217） | 载台上电 |
| 0x2009 | — | — | 预留（备用通道映射目标，DO 145~160） |

**载台上电位值规律**：偶数排=低字节从 `0x0001` 左移；奇数排=高字节从 `0x0100` 左移。例：Y110=0x2004 的 bit8=`0x0100`；Y110+Y111 同开=`0x0300`。

### 3.3 业务设备 ↔ IO（IO分配表.xlsx）

| 业务设备 | 电气 | 地址 | 通道 |
| :--- | :--- | :--- | :--- |
| 真空负压表 | NPN(漏型) | X000~X107 | DI 输入（报警硬件触点→DI，只读显示，**不参与**报警联动） |
| 真空电磁阀 | PNP(源型) | Y000~Y107 | DO 输出（控制负压） |
| 继电器(载台上电) | PNP(源型) | Y110~Y217 | DO 输出（载台 9×8 上电） |

- 八进制编址：X007 后 X010、X077 后 X100、Y107 后 Y110。第 n 点 = `X/Y + 八进制(n-1)`。
- 内部连续编号（IoMapBuilder）：输入 1~TotalInputs(80)；真空阀 = TotalInputs+deviceId；载台电 = TotalInputs+TotalBarometers+deviceId。
- NPN 低有效：触点闭合读 0 还是 1 取决于线制与 `InvertInputs`，需现场实测。

### 3.4 坑点
1. **读保持寄存器返回负值（EasyModbus 特有）**：值 ≥0x8000 被符号扩展成 int 负数，必须 `& 0xFFFF`；NModbus 返回 ushort[] 无此问题。
2. **写单点 DO 必须读-改-写**（读回→只改目标 bit→写回）；0x2004 两边业务共用，整字直写会误伤对方通道。
3. **0x2004 低字节属于电磁阀**：载台上电"全关"只清高字节、保留低字节，否则把电磁阀 65~72 一起关掉。
4. **备用通道映射**：DQ 通道烧毁时把源通道改写备用（`IoBackupChannelMappingEnabled` + `IoBackupChannelMappings`，
   格式 `源寄存器@源通道->目标寄存器@目标通道;...`，寄存器与通道均为十六进制，通道只认 0x00~0x0F（0x00=第 1 路，非法值解析直接拒绝），
   与设置界面显示完全一致（所见即所得）；程序内部自动把十六进制通道转成十进制位号运算。
   写/读 DO 自动重定向，业务侧不变；通讯测试窗体读同一配置便于现场验证。
   【V1.81】不用手写字符串：通讯测试窗通道灯右键"映射到备用通道…"（可视化连线，左点源右点目标），
   或系统设置表映射行"可视化连线…"按钮（进的是草稿，只改映射不碰开关，随设置表统一保存）；目标独占（一个备用只接一个源，新建时拦截，老配置照常加载），
   通讯窗保存写 App.config 即时生效。
   【V1.82】连线页滚轮以鼠标为中心缩放（0.5~2.5，悬停即缩），按住中键拖动画布，双击中键复位 100%。

### 3.5 排障速查

| 现象 | 排查方向 |
| :--- | :--- |
| SP 不亮 | 24V 未接/正负反 |
| SYS 红 | 网络未通/IP 不同网段；长按复位>6s 恢复出厂 |
| AL 红闪 | FP 电源未接 / IO 模块未插牢 |
| ST 闪绿不通 | 网线接触不良/不在同网段 |
| 写返回 0x80 错误码 | 地址/长度超限、模块不支持 |

## 4. 送风机（Modbus TCP 端口 50000）

### 4.1 寄存器（实测，建议一次读 6 个 0x0000~0x0005）

| 寄存器 | 功能 | 读/写 | 说明 |
| :--- | :--- | :--- | :--- |
| 0x0000 | 组合状态 | 只读 | 未使用（忽略） |
| 0x0001 | 控制/状态 | 读写 | 读：0x0000=程式停止/0x0001=程式运行中/0x0002=定值停止/0x0003=定值启动；写：0x0003=定值启动、0x0002=停止 |
| 0x0002 | 当前温度 | 只读 | 值 × 温度斜率 = °C（见 4.1.1） |
| 0x0003 | 当前湿度 | 只读 | 值 × 湿度斜率 = %RH（见 4.1.1，**与温度是两份**） |
| 0x0004 | 温度设定值 | 只读 | 值 × 温度斜率 = °C |
| 0x0005 | 湿度设定值 | 只读 | 值 × 湿度斜率 = %RH |

#### 4.1.1 定点斜率 `FanTempScale` / `FanHumidityScale`（配置项，V2.0.1）

**温度与湿度各有一份斜率**（厂商手册里两路小数位可能不同，常见 温度×0.01、湿度×0.1，
共用一份就必然有一路修不了）：

| 配置项 | 覆盖寄存器 | 内部除数 | 定点格式 | 屏显 ↔ 寄存器 |
| :--- | :--- | :--- | :--- | :--- |
| `FanTempScale`（缺省 **0.1**） | 0x0002 当前温度、0x0004 温度设定值 | 10 | 0.1 精度 | 22.2°C ↔ 222 |
| `FanHumidityScale`（缺省 **0.1**） | 0x0003 当前湿度、0x0005 湿度设定值 | 10 | 0.1 精度 | 55.0%RH ↔ 550 |
| 斜率 0.01（除数 100） | 同上各自 | 100 | 0.01 精度 | 22.20°C ↔ 2220 |
| 斜率 0.001（除数 1000） | 同上各自 | 1000 | 0.001 精度 | 22.200°C ↔ 22200 |
| 斜率 1（除数 1） | 同上各自 | 1 | 整数 | 22°C ↔ 22 |

- **两种口径的分工**：配置与界面用**斜率**（与厂商手册"×0.01"写法一致，客户看得懂、手改不容易错）；
  内部换算用**整数除数**（`原始值 ÷ 除数`，数值行为与旧实现逐位一致，不会因 0.1 这种
  二进制不精确小数引入显示误差）。两者换算只在 `DeviceConfig.ScaleToDivisor` / `FormatFanScale` 一处发生。
- **换型号时改配置**：设置表 → "冷却送风机" → **送风机温度定点斜率 / 送风机湿度定点斜率**
  （可手输下拉，档位文字写明对应哪种格式），或直接改 `App.config` 的 `FanTempScale` / `FanHumidityScale`（缺省 0.1）。
  **不用重编译**；改完下一个采集周期即生效。
- **现场核对口诀**：先读控制屏上的温度（记作 X.X），再读上位机 0x0002 原始寄存器值（记作 raw）——
  `raw×0.1 ≈ X.X` ⇒ 斜率 0.1；`raw×0.01 ≈ X.X` ⇒ 斜率 0.01；两者都不吻合 ⇒ 是寄存器地址/字节序问题，**不要靠改斜率掩盖**。
- **脏值兜底**：`0`/负数/非档位值/超范围/非数字一律回缺省 0.1（`DeviceConfig.ParseFanScale` → `NormalizeFanScale`），
  解析层再兜一道（不让温度变成无穷大或反号）。
- 改错一位就是 10 倍/100 倍的差（上位机 22.2 被显示成 2.22 或 222.0），**改完必须让现场拿主界面与控制屏对一眼**。
- **不想手工比对？长按主界面温度值自校准**（见 4.1.2，客户可自己完成，不用找开发）。

#### 4.1.2 现场自校准（V2.0.1，客户自助）

**为什么需要它**：控制器的小数位（0.1 / 0.01）是**仪表侧参数**（在控制器自己的屏上改），
Modbus 寄存器表里**没有**"当前小数位 / 当前除数"这个字段（客户协议手册第 6 章整张表都没有），
所以上位机**读不出**这台屏到底用哪个除数。
但**控制屏上显示的数值是权威值** —— 把"上位机当前读到的值"和"控制屏上的真值"一比，
就知道该换多大的比例：

```
比例 = 上位机当前读数 ÷ 控制屏真值          （例：222.0 ÷ 22.20 = 10）
新除数 = 当前除数 × 比例                    （例：10 × 10 = 100）
新斜率 = 1 ÷ 新除数                         （例：1 ÷ 100 = 0.01）
```

**操作入口（温度 / 湿度分开）**：

| 校准项 | 入口 | 说明 |
| :--- | :--- | :--- |
| **温度** | 主界面 → 右栏"监视"分组 → **长按"设置温度/当前温度"**（含标题文字共 4 个控件，按住 600ms，标签字变蓝表示已识别） | 右栏只有 290px 宽放不下独立按钮；温度标签单击本来无业务含义 |
| **湿度** | **系统设置 → 冷却送风机 → 底部【校准湿度】按钮** | 主界面不显示湿度，入口放设置表 |

**校准三步（客户照做，全程不用改代码、不用重编译）**：

1. 按上面的入口打开校准窗，窗里回显"当前"读数（上位机现在看到的值）；
2. 看**送风机控制屏上**显示的温度（或湿度），把它填进输入框
   （**输入框左侧是标题**"温度"/"湿度"，**右侧是"当前"读数**对照）；
3. 点【确定】——程序按上面的公式算出新比例（**只接受 10 的整数次幂** 1/10/100/1000/10000，
   留 5% 容差吸收"两边读数时刻不同"的温差；算不出来说明填错了，直接报错不乱改），
   自动写回对应那一个配置项并**立即重读送风机**，主界面显示当场刷新。

**一次只校一项**：温度窗只改 `FanTempScale`，湿度窗只改 `FanHumidityScale`，**互不影响**。

**为什么不写斜率寄存器**：斜率寄存器（`0x0020` 温度斜率 RW、`0x0021` 湿度斜率 RW，
乘数"以控制器当前显示精度为准"）虽然可读可写，但**写它会改变设备实际升降温速率** ——
那是客户的工艺参数，不该被一个标定动作动到。温度/湿度寄存器本来就在读，直接当探针用，零副作用。

> 校准只改上位机的换算比例，**不碰设备任何设置**；斜率同时存进 `App.config` 的
> `FanTempScale` / `FanHumidityScale`，重启后仍是校准好的值。

### 4.2 状态枚举与中文显示
`FanRunState`：0x0000=程式停止 / 0x0001=程式运行中 / 0x0002=定值停止 / 0x0003=定值启动；`Unknown(-1)`=读失败哨兵。
送风机测试窗与主窗体文案已对齐（未知态测试窗显示 "--"）；枚举用显式 switch 转中文：主窗把未知态归为"已连接"（绿），测试窗显示"--"，都不裸奔数字。

### 4.3 生命周期与 IP 识别
- 72 台共用：有任一台测试→保持运行；全部停止→才停机。`DeviceManager.UpdateFanLifecycle`（只下发一次命令）。
- 主界面无手动定值启/停按钮（自动管理，测试中手动停会被采集循环立即重启）；维护停机（全停状态下）用"送风机测试"窗口。
- **IP 自动识别**（`FanAutoDetectEnabled` + `FanIpCandidates`，配几个识别几个）：连接顺序 =
  `FanLastIp.cache`（上次成功，工控机记忆）→ FanIpAddress → FanIpCandidates；换地址自动找到并更新缓存。
- 超时：`FanTimeoutMs`（默认 3000）兼作**连接超时**（自实现 Task.WhenAny，避免 IP 错时等 20s 假死）。
- 通讯间隔建议 ≥500ms；断线后台静默持续重连（10s 节流），只在连上/断开边沿提示一次。

## 5. 扫码枪（Honeywell Xenon 1902 虚拟串口）

- **通讯参数**：115200 / 8 / None / 1，ASCII 文本流，按换行符切条码（兼容 CR/LF/CRLF）。
- **串口识别**：WMI 查询 `Win32_PnPEntity` 中名称含 `ScannerDeviceKeyword`（默认 "Xenon 1902"）的 COM 口；
  设备需先设置为**虚拟串口模式**（扫对应配置码）。
- **断连心跳**：重连定时器每次 Tick 把 WMI 动态搜索排到线程池（拔 USB 后 PnP 节点消失→判定断连），
  比注册表残留/ReadExisting 可靠；WMI 查询失败退 I/O 探测兜底。
  Tick 与 `Start()` 本身毫秒级返回：WMI 全量搜索可达分钟级，以前占 UI 线程时启动卡近 2 分钟、
  气压表/送风机状态刷不出来（V1.100 修：与 72 台采集并行）。
- **⚠️ 必须在 UI 线程启动**：`ScannerService.Start()` 内部会创建 `System.Windows.Forms.Timer`
  （重连/心跳）与 `DeviceChangeWindow`（`NativeWindow`，监听 `WM_DEVICECHANGE` 热插拔），两者都依赖 UI 消息泵；
  若在 `Task.Run` 等后台线程调用，定时器不触发、热插拔收不到消息，扫码枪拔插后无法自动重连。
  （只要求"调用在 UI 线程"，耗时 WMI 内部已转后台，调用本身不卡界面。）
- **日志只记边沿**：连上/断开各一行；`ScannerDebugLog` 默认关闭（开后心跳只在端口快照变化时记一行）。
  以前发货值误开，每 3 秒一条心跳刷屏（V1.100 关回缺省）。
- **排障**：找不到端口→确认虚拟串口模式；Access denied→端口被占用；乱码→确认 ASCII 输出。
- **串口配错**：波特率/数据位/串口超时走钳制 + `Debug` 日志明示（与气压表同一套逻辑，先看日志）。

## 6. 推荐通线验证顺序

1. 先只验证 TCP：**通讯测试窗体**（IO 耦合器页）对 GX-CL140 连接/读 DI/写 DO；预留通道走"预留点位"页（预留 DI 只读监视 + 预留 DO 点动，与备用映射目标共寄存器时自动保位）。
   打开/重连成功后三页灯自动同步现场真值（V1.101，不用先点"读取状态"）；手动点灯写失败或未连接时弹框明示且灯自动弹回（遍历/状态定时器只记日志，全部关闭失败给一条汇总）。
2. 再验证串口 RTU：**公共参数窗口**逐个写气压表阈值（只写不读），确认单位与小数位。
3. 用**送风机测试窗体**验证送风机：定值启停、读温湿度。
4. 最后联动：`UseMockCommunication=false`，观察 UI 的 IO 框与实际 IO 一致。
5. 触发报警：人为制造真空不足，确认**只在报警进入时**下发一次关阀/断电。

## 7. MES 对接（HTTP POST JSON，映射层可配；客户自助照此配，不动代码）

- **链路**：`MesReporter` 后台线程串行 POST（上报不卡采集/UI；失败永不阻断生产）。
  单入口 `MesEndpoint`（完整 URL），事件类型在 JSON 的 `event` 字段区分。
  `Content-Type: application/json`；`HttpClient` 进程单例复用；鉴权头挂请求头。
- **触发器**（`MesTriggers`，跟项目，留空=全开）：`Start` 启动 / `Complete` 完成 /
  `Alarm` 报警 / `UnloadJudge` 下料判定。完成带时长+判定结果，报警带压力值，
  下料带不良代码+处置。大小写无所谓，去重保序；未知触发器保存时拦、上报时跳过。
- **字段映射**（`MesFieldMap`，跟项目）："MES名=本站名"分号分隔，如 `eqId=device;lotNo=lot`；
  本站 vocabulary：time/lot/device/event/sn/recipe/result/detail/pressure/temp/
  duration/displayMode/project/disposition/defectCode；留空=直通。
  改名是真改名（命中映射的本站原名删除，不双发）；本站键大小写不敏感匹配；
  脏组保存时拦、上报时跳过该组。分隔符中英文逗号/分号/顿号都认。
- **静态字段**（`MesStaticFields`，跟项目）：如 `line=L5;workshop=A3`，原样并入每次上报；
  同名覆盖映射结果（常量优先）。值是字面量，不校验 vocabulary。
- **鉴权**（跟机器）：`MesAuthType` None/Bearer/Basic + token/用户名/密码
  （保存时 DPAPI 加密落盘，前缀 `DPAPI:`，内存里是明文，解密失败按空+记日志；
  无此前缀的一律按非法处理，不做明文兼容——配错重填。DPAPI 是本机机器级密钥，
  换工控机必须重填鉴权，拷配置文件带不走）。
- **自定义头**（跟机器）：`MesCustomHeaders`（如 `X-Line=L5;X-ApiVer=2`；
  头名纯 ASCII token：字母开头，仅字母数字加 `-_.`，中文/空格一律拒绝；
  与鉴权头同名时鉴权优先，顶不掉）。
- **按事件分地址**（跟机器）：`MesEndpointMap`（如 `Alarm=http://192.168.1.50:8080/api/alarm`；
  触发器=URL，URL 必须 http(s):// 开头；没配的事件回退默认地址；重复触发器后者覆盖）。
- **可靠**：失败按 `MesRetryCount`（默认 3，0=只发一次）/`MesRetryIntervalMs`
  （默认 2000ms）重试，全灭进离线缓存 `MesQueue.json`（程序目录绝对路径，
  原子写，上限 5000 丢最旧；内存队列上限 2000，超限丢最旧并记一条事件）。
  下次成功时先冲旧缓存再发新的（保序）；退出时内存余量转存缓存再走。
  成功口径：HTTP 2xx；其余状态码/异常一律算失败。
- **联调**：`MesMockEnabled=true` 不发 HTTP，只写"MES上报(Mock)"事件到 CSV（含完整 JSON）——
  MES 没好也能先验格式；启动日志首行即显示 MES 状态（开/关、往哪发、Mock 还是真发）。
  总开关 `MesEnabled=false` 时零线程零开销；开关开了没配地址保存即拦（上报侧静默跳过兜底）。
- **排障**：MES 收不到→先看启动日志确认开关与地址；CSV 有上报事件但 MES 无→查 URL/鉴权/防火墙；
  `MesQueue.json` 一直在长大→网络或 MES 侧不通（2xx 才算成功）。
- **改代码边界**：协议不是 POST JSON / 要第 16 个本站字段（vocabulary 冻结 15 个，
  加字段改 `MesMapping`+组包+用例）/ 新触发时机（加 `Report` 埋点）/
  嵌套 JSON 或 XML / 按 MES 返回做业务动作——才动代码，其余全是配置。
