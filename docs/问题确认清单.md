# 问题确认清单

## 附图：软件里现在跑的就是这个逻辑（单台工位视角，与代码逐条对过）

```
空闲 ──[点启动]──► 只开真空阀，不带电（抽真空Vacuuming阶段）
                          │
         ┌────────────────┼──────────────┐
         │                │              │
    真空到位 且        超时还没到位      连续读失败N次
    延时开启到       （默认15秒可配）   （默认3次可配）
    （等于阈值              │              │
     算到位）               ▼              ▼
         │           报压力越限FAIL   报设备异常
         ▼           关阀＋断电       关阀＋断电
    载台上电，         面板标故障红    面板标故障红
    开始计时           永不带电        不记产品FAIL
    （计时起点=上电时刻，
    参数启动瞬间定格）
         │
         ├──── 老化中失压/掉线同样报警（与抽真空阶段同动作）──►FAIL/设备异常
         │
    时间一到（配方时长优先、全局兜底；都为0=不限时长永不自动完成）
         │
         ▼
    自动下电＋关阀（关阀≠泄压，残压还在，无自动破空/无响铃）
    面板淡钢蓝"已完成"（日志记PASS·待取料）
```

- **停止 vs 复位（易混）**：手动停止只中止Testing/Vacuuming/Aging回空闲，清不掉红/蓝屏；
  故障红/完成蓝必须按“报警复位”或重新扫码绑SN才回空闲。急停=全部输出OFF+停风机，但红/蓝标记同样保留到复位。
- **断电来电**：重启询问“整台重测（满时长重跑，已跑作废） / 放弃（安全关阀断电）”。
- **合格口径**：全程无报警＝PASS；压力越限/超时＝FAIL（产品责任）；通讯失联＝设备异常（不记产品 FAIL）。
  （V1.67 起均为策略缺省：真空类可切装夹异常 / 完成可切待判定，见本节末落子；下图是缺省行为。）
- 图里“延时开启/老化时长/负压阈值”配方优先、全局兜底，启动瞬间定格，中途改配方不影响在跑的台。

## 一、问题确认

### 对工艺

1. **真空到底干什么用的？**
   当面问："漏气这台货，你们算治具问题还是产品不良？"
   - 治具问题 → 现状不动，只验阈值参数。
   - 产品不良 → 报警要关联 SN 记不合格，回来改判定逻辑（约 0.5~1 天）。
   追问一句："摆料时产品靠什么固定？一松手掉吗？"掉 → 加回"装夹预吸附"入口（带压力监控）。
   【已可配】`VacuumFailKind`（产品责任 ProductFail / 治具责任 FixtureAlarm，可重测）。
   入口：系统设置→工艺策略 / 工艺策略窗→报警联动节点；跟项目走（切项目即换，缺省=产品责任现状）。

2. **载台给产品供什么电？要不要监测电流？**
   当面问："多少V？直流交流？谁供电？老化中看不看电流/功率？"
   - 要回采 → 加电流表通讯，最大工作量项，单独排期，**不当场承诺时间**。
   【不可配·二期硬件】全仓无电流寄存器/配置/界面，回采需加硬件+改代码，不在可视化范围内。

3. **送风是加热还是冷却？温度谁说了算？超温停单台还是全线？**
   - 软件设温 → 现协议无写温度寄存器，需找风机厂商，先记二期。
   【半可配·现状已定】温度控制由设备商自带控制屏做好，上位机只做"定值启停+读温湿度"（详见通讯接入.md §4）。
   上位机可配的是断连/超温动作（见 Q16），加热/冷却是物理事实不用配；全机单探头，只有"全线停"一种动作。

4. **老化合格谁说了算？在哪看结果？**
   现状口径：全程无报警=PASS、压力报警=FAIL、失联=设备异常（不记产品 FAIL）。
   只确认：接受否 + 判定人 + 结果在哪看（屏幕/报表/MES）。
   【已可配】`CompletionJudgePolicy`（自动PASS AutoPass / 待判定 PendingReview+下料人工录PASS/FAIL+不良代码+处置，进CSV追溯）。
   结果出口：屏幕面板+历史查询（现状）/ CSV明细（现状）/ MES四事件上报（`MesTriggers`，见Q10）。直通率/曲线/SN追溯单需现做（见Q8）。

### 对操作员

5. **一批放多少？做完一个换一个还是一批同进同出？批号怎么定？混批吗？**
   【管理制度·不用配】批号录入（录入批号窗，扫码枪自动填）与配方批量下发已实现；批号规则/混批允许否是车间制度，
   无开关，定死后列入培训。注意批号仅事件传递未落盘（README §10待办），追溯靠SN+CSV。
6. **到时完成后你们希望怎样？自动下电够吗，要不要自动泄压/响一声？**
   【已可配】`CompletionAction`（只下电关阀 / 下电+蜂鸣 / 下电+破空泄压 / 都要）+ `VentValveDoPoint`（点位0=未接硬件只记日志）
   + `VentValveEnabled`（本机有无阀，关则藏按钮+泄压保存即拦）。入口：工艺策略窗→完成下电节点；动作/点位跟项目，开关跟机器。
7. **报警的货现在怎么处理？复位谁来按？**
   【半可配】记什么可配（`VacuumFailKind`：FAIL vs 装夹异常可重测）；重测/报废/降级走哪条线、复位谁来按是管理制度，
   无开关，定死按的人列入培训。

### 对质量

8. **报表要什么样？最好直接拿一张现有纸质/Excel 照抄。**
   现状只有 CSV 明细 + 历史查询；直通率/曲线/SN 追溯单都要现做。
   【不可配·二期待做】无报表格式配置项，拿到样张后现做，不当场承诺。

### 对电气/IT

9. **载台供电方式 + 真空管路走向 + 送风管道，拍照。**
   【现场资料·不用配】拍完归档，不进软件。
10. **MES/ERP 有无硬性对接要求？接口形式？**
   【已可配·映射层】`MesEnabled`/`MesMockEnabled`（Mock只写CSV不发HTTP，先验格式）+ `MesEndpoint`/`MesAuthType`/
   token/密码（DPAPI加密）/`MesRetryCount`/`MesRetryIntervalMs`/`MesCustomHeaders`/`MesEndpointMap`（跟机器）
   + `MesTriggers`/`MesFieldMap`/`MesStaticFields`（跟项目，工艺策略窗→MES上报节点）。
   每家握手/事务差异仍需二期定制，映射层已覆盖90%。

### 补充确认点

11. **老化中掉真空停不停？**
    现状：抽真空阶段和上电老化中失压/掉线同样关阀断电（压力类=FAIL，失联=设备异常）。只确认接受否。
    【已可配】`AgingPressureLossPolicy`（停机报警 StopOnLoss / 只记不停 KeepRunning，只管Aging阶段，抽真空失败永远报警）。
    入口：工艺策略窗→报警联动节点；跟项目走。
12. **15秒超时 + 连续3次失联够吗？**
    现状默认值，可在系统设置改。当面测一次从常压抽到阈值要几秒，回填§三参数表。
    【已可配·跟机器】`VacuumConfirmTimeoutMs`（默认15000）+ `CommunicationLossAlarmCount`（默认3）。
    入口：工艺策略窗→抽真空节点 / 系统设置；注意切项目不换（机器级），多项目共机需手工对值。
13. **所有配方启动时间都大于0吗？空SN/空配方让不让启动？**
    现状：配方与全局都为0=不限时长、永不自动完成；空SN/空配方也能点启动。要不要软件拦截？
    【已可配】`ZeroDurationPolicy` / `EmptySnPolicy`（Warn=警告可继续现状 / Block=硬拦截）。
    入口：工艺策略窗→启动开阀节点；跟项目走。烧屏项目建议Block（防无限点亮）。
14. **完成/故障回空闲谁来按？**
    现状：手动停止清不掉红/蓝屏，必须按"报警复位"或重新扫码才回空闲。定死按的人，列入培训。
    【固定逻辑·不用配】回空闲路径写死（复位/重绑SN/下料判定），无开关。
15. **完成后产品徒手能拿下吗？（关联Q6）**
    现状：关阀≠泄压，无自动破空、无响铃。现场试一次拿不拿得下，决定加破空阀/声光否。
    【已可配·同Q6】拿不下→`CompletionAction`选泄压+填`VentValveDoPoint`+开`VentValveEnabled`；只想提醒→选蜂鸣（无需硬件）。
    本机无阀保持默认即可。
16. **风机断连/超温允不允许继续跑？（关联Q3）**
    现状：风机掉了测试照跑只记一行日志；极限温度默认0=禁用。回填极限温度，定断连阻断否、超温联停否。
    【已可配】`FanDisconnectPolicy`（只提示LogOnly / 阻断启动BlockStart，只管启动那一下，跟项目）
    + `FanTempAlarmLimitC`（上限，0=禁用，跟机器） + `FanTempShutdownEnabled`（超温全线联停，跟项目）。
    注意开关与阈值分家：切项目后阈值不换，需手工对值；单探头只有全线停。
17. **DI硬件触点并入报警吗？**
    现状：`UseDiAlarmContact=false`仅显示不联锁。开了要先确认常开/常闭+NPN电平，否则误报/漏报。
    【已可配·跟机器】`UseDiAlarmContact`开关 + `InvertInputs`取反（电平兜底）。入口：报警联动节点 / 系统设置；
    切项目不换，开之前必须确认电平。
18. **定格语义接受吗？**
    现状：启动瞬间抄配方，中途改配方旧台按旧参数跑完。接受 / 不接受（不接受=大改，排期重议）。
    【固定逻辑·不可配】无"实时跟随"开关，接受即签字，不接受走改造清单排期。

## 四、MicroLED 烧屏锚（V1.65 调研推断，现场只答 yes/no，不动代码）

- **客户身份推断**：合肥显耀 = JBD（显耀股份）合肥工厂，产品为 0.5 英寸以下 MicroLED 微显示屏
  （AR 眼镜/HUD/微投影用，合肥一期 2023-10 竣工、规划年产 1.2 亿套）。设备标签"烧屏"=
  显示行业对"通电老化"的俗称（非 OLED 残影缺陷）。本设备定位=**老化段（点亮+计时+保护+追溯），
  光学判定在后道检测设备**（JBD 2026-03 与精测电子战略合作，精测做点灯检测/Demura）。
- **形态推断**：72 小工位（电视屏物理上放不下 72 块）+ 真空吸附固定微小模组 +
  真空到位才上电（= 探针/pogo 接触保护）+ 载台只供电不控画面（画面由治具驱动板/外部 PG 给）。
- **风险推断**：MicroLED 微显示亮度极高、发热大，72 台 24h 点亮 + 温度只显示不联锁，
  是当前最大安全缺口（见 Q21）。

19. **真空用途 yes/no**：我们的推断=吸附固定+探针接触确认；漏气算治具（可重测、不记产品 FAIL）？
    - yes → 真空失败改记"装夹异常"（P1-❸，纯软件 0.5 天）。
    - no（算产品不良）→ 现状不动，只验阈值参数。（关联 Q1）
    【已可配·同Q1】yes→`VacuumFailKind=FixtureAlarm`，no→`ProductFail`，工艺策略窗改，不动代码。
20. **老化工艺回填**：老化时长几小时？画面是什么（白场 / RGB 循环 / 棋盘格 / 视频，分段吗）？
    现状时长全 0=不限时长永不完成，对烧屏=无限点亮（过老化+火灾风险），必须改为必填拦截。
    - 回填 → 配方设默认值 + 启动拦截 0 时长（P1-❺，0.5 天）+ 配方加"显示模式"字段追溯（P2-❼）。
    （关联 Q13）
    【半可配】时长部分已可配：配方`StartTime`设默认值 + `ZeroDurationPolicy=Block`硬拦截（启动节点）；
    画面部分不可配：`DisplayMode`只记追溯（配方三窗+启动/报警日志），不控PG切画面，画面分段/视频走二期。
21. **断电续跑 + 超温动作二选一**：①断电后来电"续跑（补足剩余时长）/重测"能接受续跑吗？
    （现状整台重测：浪费产能 + 同一批衰减算两次，影响后道 Demura 基准。P1-❻，约 1 天）
    ②超温停单台还是全线？（现状只显示不限停；风机温度+配方极限温度现成，只差接进报警。
    P1-❹，纯软件 1 天；烟感走预留 DI，硬件另计。关联 Q3/Q16/Q17）
    （关联 Q11）
    【已可配】①`PowerLossPolicy`（整台重测 RestartFull / 续跑剩余 ResumeRemaining，断电恢复节点，跟项目）；
    ②`FanTempShutdownEnabled`+`FanTempAlarmLimitC`（全线联停，见Q16；单台等硬件分区探头，烟感硬件另计）。
22. **下料判定口径**：现状到时自动记 PASS。显示行业惯例"老化≠合格"（后道必检坏点/亮暗点/
    线/闪烁/Mura/色偏），接受改成"完成=待判定，下料扫码录 PASS/FAIL+不良代码"吗？
    不接受=追溯数据持续假阳性。（P0-❷，约 1~2 天。关联 Q4）
    【已可配·同Q4】`CompletionJudgePolicy=PendingReview`即切待判定（完成下电节点，跟项目），操作区下料判定按钮录入。
